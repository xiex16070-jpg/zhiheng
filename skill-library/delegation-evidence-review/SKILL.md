# 委派后的证据复核

## 流程
1. 先判断任务能否独立拆分。多篇论文或不同论证角度可以各自检索；依赖前一步结论的步骤保持顺序。简单问题直接处理。
2. 用 update_plan 列出交付目标，再把独立任务交给 delegate_task。每项写清研究问题、可用资料范围和输出要求；子代理看不到完整父对话，背景必须自包含。
3. 请子代理返回结论、真实来源标记、原文定位、相反证据和未解决问题。子代理只有只读能力，涉及写文件、外部服务启用或审批的操作交回主任务。
4. 汇总时按论断逐条比较来源。两份报告引用同一论文只算一个独立来源；来源标记未进入当前证据集合时先重新检索，不能直接作为最终引用。
5. 对关键结论用 read_source 读原文，逐字引文用 verify_quote 核验。子代理的完成状态说明执行已结束，并不能证明论断成立。
6. 对结论冲突先比较研究对象、假设、版本和测量口径；仍不能消解时并列呈现。证据不足的部分明确留空，别靠投票得出科学结论。
7. 在最终交付中说明综合结果及限制。缓存命中、子代理转述、主任务实际核验分别据实表述；需要导出时复用 create_document 或 write_file。

## 完成检查
- 每个重要论断都有当前任务可追溯的来源，反例没有因多数意见被删掉。
- 预算耗尽或部分子任务失败时保留已验证结果，并明确缺失部分。
- 任务结束的可复用经验应是已验证的方法；临时限流或未配置依赖不升级为永久的工具禁令。
