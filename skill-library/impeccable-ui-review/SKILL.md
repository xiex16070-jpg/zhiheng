# 审查聊天、执行与证据界面

先选定一条用户路径，例如「发送长问题 → 等待工具审批 → 阅读回答 → 从引用回到原文」。记录当前实现采用的组件、设计变量和适用的工作台规范。使用公开示例或合成数据复现。

- 聊天：在新消息与流式更新之间检查阅读位置和键盘焦点。观察长问题、长答案、取消与重试时操作是否清楚、草稿是否保留。
- 执行：对照真实事件检查等待、已完成、失败和审批。点按阶段摘要，确认展开后能到达对应步骤。减少动态效果时，用文字和图标识别同一状态。
- 证据：先区分原文、模型归纳和证据不足，再沿一个已返回的引用进入来源并回到触发点。检查缺失来源、多个引用和长标题；空引用不应成为可点击的死路。

用键盘、窄屏及明暗主题复核发现。每个问题给出触发操作、观察结果、对任务的影响及可复验的修复条件。只有实际操作过的交互才记录为已验证；只能读代码时写明待测条件。实施修复时优先复用现有组件和视觉规范。
