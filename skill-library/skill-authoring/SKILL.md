# 技能写作

## 何时值得写
- 同类问题出现过 ≥2 次，且解法有固定步骤。
- 步骤里有容易踩的坑（顺序、参数、边界），写下来能少走弯路。

## 结构
1. 一句话触发条件（Use when…），写清什么信号出现时该用它。
2. 步骤按执行顺序编号，每步一个动作，不写「综合考虑」。
3. 反例单列：最容易做错的两三件事。
4. 名称用类级 kebab-case（retrieval-query-recovery），不要写「修复某某 bug」这种一次性叙事。

## 禁令
- 不把「某工具报错了」写成「该工具不可用」——环境问题不是知识。
- 不写未验证的结论；不确定的部分标注「待验证」。
- 一课一条，不要把所有经验塞进一个技能。
