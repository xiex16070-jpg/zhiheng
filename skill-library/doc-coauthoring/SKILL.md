# 文档协作

## 流程
1. **对齐意图**：先问清读者、用途、长度、必须包含/必须避免的内容；一次只问最关键的两三个问题。
2. **先给骨架**：只给章节标题与每节一句话要点，等确认后再写正文。骨架阶段改动的成本最低。
3. **分段交付**：每次写 1-2 节，写完说明「这一节用了哪些证据/还缺什么」，让用户能逐段纠偏。
4. **留痕修订**：用户改过的措辞保留，不「顺手优化」；需要重写时先说明为什么。
5. **收尾自检**：术语一致、编号连续、引用可回跳、结论与证据强度匹配。

## 反模式
- 一口气写完再让用户提意见——返工成本最高。
- 把用户的修改又改回去。
- 骨架没定就纠结措辞。
