# 头脑风暴

## 用法
用户说「有什么思路/怎么做更好/给我几个方案」时，先发散再收敛；不要第一句就给单一方案。

## 流程
1. 复述目标与约束（时间、数据、预算、不能动的东西）。
2. 给 4-6 个**明显不同**的方案，每个一句话机制 + 适用条件 + 主要代价。
3. 用一张小表对比（成本/见效速度/风险/可逆性）。
4. 给出推荐，并说明「什么情况下不选它」。
5. 用户选定后再展开执行细节。

## 纪律
- 不把同一方案的三个变体算三个方案。
- 不隐藏代价；推荐项也要写风险。
- 发散阶段不写实现细节，收敛后再写。
