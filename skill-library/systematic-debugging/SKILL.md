# 系统化排查

## 四阶段
1. **复现**：拿到最小可复现输入；不能复现就先加日志/探针，不要猜。
2. **定位**：沿调用链二分（输入→中间态→输出），每步只验证一个假设；一次改多个变量等于没排查。
3. **根因**：问「为什么」到能解释所有现象为止；只解释部分现象的是症状不是根因。
4. **验证**：先写失败测试再修；修完跑全量，确认没有把别的路径弄坏。

## 纪律
- 读错误信息原文，不读自己脑补的版本。
- 先看最近改动（git diff / 日志时间线），再看历史遗留。
- 修完在提交信息里写清「现象—根因—修法」，方便下一个人。
