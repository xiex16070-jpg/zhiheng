# 交付前自检

## 清单
1. 用户要的每一项都做了吗？逐条对照原始请求，不按自己的理解打分。
2. 声称「已生成/已修复/已通过」的，有没有真实产出或测试输出支撑？
3. 改动是否触及未预期的文件？跑一次全量测试而不是只跑新增用例。
4. 边界情况：空输入、超长输入、并发、权限不足，各是什么行为？
5. 交付说明写「已验证/未验证」，不写「应该可以」。

## 反模式
- 用「已完成」代替证据。
- 只跑一个用例就宣布全绿。
- 把「没报错」当成「功能正确」。
