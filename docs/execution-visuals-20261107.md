# 执行过程视图与证据折叠 · 2026-11-07

逐句证据审核、引用来源和模型推断评估现在都默认折叠，历史会话回放采用相同规则。原文冲突或依据不足仍保留正文内的提示；用户可以用鼠标或键盘展开核对。

## 界面行为

- 三类结尾信息共用原生 `details/summary`，统一图标、摘要、数量和展开/收起按钮。新消息和历史回放均不自动展开问题审核。
- 执行过程默认折叠，内部步骤和技术记录也默认折叠；用户已展开的节点不会因流式文本或状态更新被替换。审批需要操作时继续直接展示，防止把批准按钮藏起来。
- 过程顶部按实际事件提供准备、取证、求解、行动、核查、交付等阶段入口。只出现已经发生的阶段，点击定位对应节点；状态表示运行结果，不表示回答正确。
- 检索节点显示真实通道命中条和统计；模型/工具轮次以调用节点呈现，工具名称改为可读中文。
- IRCoT 显示逐层追检、命中与新增记录；ToT 显示父子路径、实际相关性得分和选中路径。相关性分数不解释成结论正确的概率。
- 规则推演显示前提编号、规则、结论和来源的证明节点。聊天内的推演及证明图默认折叠，完整 JSON 下载仍保留全部节点，界面仍只显示前100条。

历史记录没有逐路径数据时，只显示原有统计并说明数据缺失，不补造算法过程。无证据回答也不会主动展开执行轨迹。

## 数据与性能边界

`runResearchStrategy` 新增的 `process` 仅记录实际检索操作的编号、父节点、层级、状态、命中数、新增数和已计算的分数。IRCoT 最多两次追检，ToT 沿用既有三条首层路径和至多两个扩展。调用数量、检索选择、评分和提示词均未调整；没有新增模型请求。

过程元数据随任务结果和步骤记录保存，支持回放。新字段不包含查询文本、文档摘录或模型内部推理文本。原有参数技术记录仍使用执行层已有的脱敏结果。

时间线按尝试次数和调用ID保留稳定节点；步骤事件携带尝试号，避免恢复任务时覆盖前次尝试。同一工具的不同调用分别计数。更新只改发生变化的可视节点，沿用原生布局和现有主题，无新增动画库或常驻图形渲染循环。尊重系统减少动态效果设置。
