- 用户连续启动看到“3000 起尝试 10 个端口均未就绪”，服务日志则显示“此数据目录已有服务实例运行”。

## 修改与边界

- `runtime-lock.mjs` 在原本跨进程独占锁上提供只读身份查询：协议版本、进程号、bootId、实际监听地址/端口、初始化状态；不包含问题、文档、密钥或执行命令。
- `launch.mjs` 按数据目录查询活跃实例，匹配 HTTP 状态码、bootId 和就绪状态后复用；无实例才启动。同目录并发启动的竞争者发现胜出实例后复用，不删除兼容 PID/端口文件。
- IPC 明确空响应（旧协议）与查询超时分开处理：旧协议要求先确认旧实例，初始化阻塞导致的临时超时继续等待。最长等待 45 秒，只可能终止本次启动器创建的子进程，不终止既有或无法识别的实例。
- `stop.mjs` 二次核对活跃锁的 PID/bootId 后才发送停止信号，随后确认锁释放。忽略 PID 文件内容，拒绝对未知旧协议实例盲目操作；Windows 的 Node SIGTERM 不能保证执行异步退出回调，兼容记录可能残留，但新启动器不以它作为权威。
- 启停脚本共用配置解析，支持自定义 `DATA_DIR`、`PORT`；相对路径以项目根目录解析。服务报告实际绑定地址，兼容 `localhost` 的 IPv4/IPv6 解析差异。
- 健康探测使用实际监听地址，浏览器继续使用原有 `localhost` 地址，避免切成 IP 后因浏览器源不同而看不到原有会话身份或界面偏好。
- 服务回探处理响应中断、错误、体积上限，并将“最多 10 个端口”修正为准确的 10 次尝试。未扩大网页、文件、模型或工具权限。
