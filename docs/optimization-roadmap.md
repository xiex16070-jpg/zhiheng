# 优化路线图（Optimization Roadmap）

> **2026-11-02 复审**：main 已前进到 `4d03617`，部分问题已修复、并出现新问题 N-01~N-19。最新状态见 `docs/audit-main-4d03617.md`；新增任务见 `specs/001-system-optimization/tasks.md` 的「Phase R」（R01–R04 为新的最高优先级）。

> 依据：`docs/architecture-audit.md`（问题编号 A-xx）。任务细节见 `specs/001-system-optimization/tasks.md`（任务编号 Txxx）。
> 原则：先止血（安全、可用性）→ 再保正确（数据完整、回答可信）→ 再提质量（检索与 Agent）→ 最后才是性能与扩展。
> 每个阶段结束都必须满足"阶段出口条件"后才进入下一阶段。

## 不做的事（避免过度设计）

- 不引入 Web 框架、ORM、前端构建工具、向量数据库 SDK。
- 不更换 RRF 融合思路；不引入 LangChain/LlamaIndex 等编排框架。
- 不实现完整账户体系（注册/密码/OAuth）；Phase 0 只做"服务端签发、不可伪造"的匿名会话。
- 不重写 PDF 解析器。

## 回滚策略总则

- 每个任务单独提交，提交信息包含任务 ID；回滚即 `git revert <commit>`。
- 涉及配置的新行为都有环境变量开关，默认值写在 tasks.md 中；需要紧急回退时可先改环境变量，再决定是否 revert。
- 涉及数据格式的任务（T101、T206）必须向后兼容读取旧格式。
