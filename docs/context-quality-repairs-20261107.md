# 本地上下文、交付约束与评测后续修复

用户授权按上下文与回答退化、依赖、人工评测、后端能力的顺序处理。基础为主库 `4c97353`、模型实验库 `5790289`；未重训、修改原始权重、修改冻结题或扩大输出预算。

## 上下文与回答

`local-context.mjs` 在每次本地模型请求前用配套 tokenizer 测量完整消息和工具定义。超出输入加 384 输出预算时，只将较旧的 search_knowledge/read_source 摘录投影成来源目录，保留最新工具观察、系统提示、全部用户消息、工具参数与配对、错误和审批。来源身份、标题及外部权威属性保留，省略不能解释为无证据；需要原句时仍可 read_source。

原始工具消息、SHA-256、轮次、压缩前后 token 数先进入任务属主隔离的 checkpoint，再向模型发送投影。完成后保留只读归档，删除可恢复消息；学习关闭也不丢归档。step/SSE 只记录元数据，不把原文发送到追踪服务。投影后重新实测 token；不能容纳的用户长输入仍明确失败，不删用户约束、不降低输出预算。控制标记在压缩前检查。

兜底收尾先加入完整提示，再计数；修复原先先检查后追加提示的不一致。

`local-answer-check.mjs` 对未知来源编号、用户明确要求的逐字引文缺失做最多一次交付纠正，使用原有主调用次数预算，次数跨恢复持久化。没有扩大调用上限，没有自动生成引文、修改最终答案或假称语义验证。原始输出进入既有调用快照；显式 NO_EVIDENCE 不强制补引用。最终 `answerContract` 公开未解决问题和修复次数。

逻辑工具结果额外提供与原始四值状态逐项对应的中文 verdict，保持查询顺序、原程序与证明范围不变，避免将 unknown 当成 false。框架修复不能证明 v5 权重回归已消失；适配器继续未晋升。

调用快照同时保留脱敏后的后端能力和工具模式。发生过交付纠正、仍有未解决交付问题的轨迹，即使最后被点赞，也不整条导出为正向 SFT；错误草稿与纠正过程仍可供人工整理，避免把错误中间回答当作训练目标。旧的无新字段记录保持兼容。

## 验证协议

先冻结实现，再用同一真实 Qwen 服务分别跑旧框架隔离 worktree 和新框架。基座与 v5 分别对比，保持公开 712 节教材、题目、评分、profile、NF4/BF16、256 prefill、4096 上下文、384 输出及最多 3 个工具轮次不变；第 4 次为原有无工具收尾。模型工作流使用原有 local-hash 隔离检索，不冒称 BGE 端到端实验。

另外重跑基座/v5 固定 32 题；该套题直接调用模型，不经过新增交付纠正，原始权重能力与框架效果分开统计。失败、未完成、上下文拒绝均计入分母；逐次原始响应保留于本机忽略目录。运行使用 MLflow 实验 `zhiheng-context-quality-20261107`，源码、题集、模型、runtime 身份与报告 SHA 留痕。

全量回归首次暴露既有 kb-sections 测试继承生产 BGE 配置的问题；修复测试自己的 embedding 环境隔离，未改生产配置。新增真实 HTTP 夹具验证压力投影、审批重启恢复、完成后归档、跨用户隔离和不可重复恢复；夹具不计入真实模型质量。

v5 的 6 次旧摘录归档均有原消息 SHA 可核对；这些请求的输入合计从 23234 降为 21250 token。实际 54/54 次生成均匹配完整输入加输出预算，没有无法验证或越界的生成。流程结束不等于回答正确，不能把 20/20 写成质量通过率。

冻结评分器把“压缩前超限、压缩后合法”的预检也算失败。保留原严格 5/20；另列同规则应用到两侧的预算诊断 5/20 → 6/20，只用于解释预算行为，不用于晋升。没有重写冻结评分器。旧框架缺失的 answerContract 记为未知，不冒充零问题。

基座的 8 次交付纠正仍未满足逐字引文要求，模型调用从 37 增至 45，严格通过数没有改善；v5 调用从 41 增至 54。保留这些负向结果，不把纠正机制描述为已经解决回答质量。自然语言的语义支持仍需要独立人工评测。
